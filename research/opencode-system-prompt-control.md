# opencode: Control of the Core System Prompt

Status: **Unverified — needs a 30-minute spike.** Captured here so the finding survives session gaps.

## Problem

opencode's core system prompt (tool definitions, permission rules, mode descriptions, skill-list preamble) is generated by the binary. The standard configuration surface (`opencode.json`, `AGENTS.md`, agent files, skills) only shapes the layers *around* it — it cannot trim or rewrite the core. That makes every turn pay a fixed token cost the user cannot reduce.

## Known levers (already exhausted)

These shape surrounding context but do **not** touch the core prompt:

- `opencode.json` → `instructions`, `agent`, `default_agent`, `disabled_providers`, `lsp: false`, `formatter: false`.
- `AGENTS.md` — loaded into every agent's context.
- Agent files (`.opencode/agent/<name>..md`) — override built-ins or define custom agents.
- Disabling unused skills — removes their *descriptions* from the always-listed skill preamble.

## The lever not yet tried: `experimental.chat.system.transform`

Plugin hook surfaced by the `customize-opencode` skill. Per the skill docs, plugin hooks can mutate `output` in place before the request is sent. Relevant hooks:

- `experimental.chat.system.transform` — mutate the system prompt content.
- `experimental.chat.messages.transform` — mutate the message history.

## Caveats

- `experimental.*` — no stability guarantee across opencode versions. Pin the version or accept re-audit cost on upgrade.
- Untested by the author of this note. Treat the signature as approximate until confirmed at runtime.
- Forking `sst/opencode` and editing the prompt templates directly is the fallback if the hook is insufficient — but that's a maintenance burden for a solo maintainer on 14-day rotations. Try the hook first.

## Switch criteria (only revisit if the spike fails)

A switch to another harness only makes sense if **all** of:

1. The `system.transform` hook does not give sufficient control after a real test.
2. Forking opencode is too much maintenance solo.
3. An alternative harness is both more hackable *and* preserves the tooling relied on (MCP, skills, agents, subagents).

Initial read: most alternatives (Claude Code, Cursor, etc.) have the same baked-prompt problem with weaker escape hatches than opencode's plugin system. Aider is more hackable but a thinner harness. Total control would require rolling our own against the approved Claude API — rebuilding a lot. Expectation: the spike will succeed and no switch is needed.
